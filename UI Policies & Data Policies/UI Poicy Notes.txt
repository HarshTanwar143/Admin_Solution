Yes — use this no-script trick:

1. In **Conditions**, click **Add Filter Condition**.
2. Choose field: **Created** (sys_created_on)
3. Operator: **is not empty**
4. Leave **On load** ✅ checked, **Reverse if false** ✅ checked.
5. Save.

**Why this works:** A new record has no "Created" date yet (it's blank until saved), but an existing record already has one. So:
- New record → Created is empty → condition false → not read-only
- Existing record → Created is not empty → condition true → read-only ✅

Do this for both policies (Branch Code and Account Number).

"Clear the field value" — if checked, it wipes out whatever value is in that 
field whenever this UI Policy action triggers.
Example: Say you have a policy: "If Account Type = Closed → clear Current 
Balance." When someone marks the account as Closed, the Current Balance field 
automatically gets emptied out (set to blank/0), instead of just becoming 
read-only with the old value still sitting there

imp:
**Global** = should this UI Policy apply to **all views** of the form (Default, Mobile, Service Portal, etc.) or just one specific view.

**Example:** Say your Transaction form has two views — "Default" and "Mobile". If **Global ✅ is checked**, your "Account & Amount mandatory" rule applies on both Default and Mobile views. If **unchecked**, it only applies to whichever one view you pick (e.g. only Default) — the Mobile view won't enforce it.

For your case, keep it ✅ checked — you want the rule everywhere, not just one view.
