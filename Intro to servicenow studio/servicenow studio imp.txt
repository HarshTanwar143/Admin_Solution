Question : then if i have to do everything through main dashboard then why there 
is this servicenow studio? 

Answer:
Because they have different purposes:

ServiceNow Studio → Used by developers to build applications (tables, scripts, flows, modules, UI policies, etc.).
Main ServiceNow Dashboard (Platform UI) → Used to manage data and administration (users, groups, roles, incidents, requests, approvals, etc.).

In short:
Studio = Build the application.
Main Dashboard = Use and administer the application.

Answer: 
**No, it is not violating scope isolation.**

**Why?**

* **Groups (`sys_user_group`) are global platform records**, not scoped application records.
* **Application scope isolates application artifacts** (tables, scripts, UI policies, etc.), **not platform data** like users, 
groups, and roles.

So your Banking app can still see the TechNova groups because they exist in the shared **`sys_user_group`** table.

**In short:**
**Scope isolates app components, not shared platform records like Users and Groups.**

By default, **creating a delegate does not require approval**. It simply creates a delegation record. Whether approval is 
needed depends on how the ServiceNow instance has been configured.

### Scenario 1: You are an Admin and create a delegate

* ✅ Usually **no approval** is required.
* The delegate becomes active immediately (based on the start/end dates).

### Scenario 2: You are a normal user and create a delegate for yourself

* ✅ By default, **no approval** is required.
* If you have permission to create delegation records, the delegation becomes active immediately.

**In short:**
**Default ServiceNow:** ❌ No approval for delegate creation.
**Customized instance:** ✅ Approval may be added if the organization configures it.
