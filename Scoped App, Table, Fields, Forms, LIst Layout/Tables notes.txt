What is sys_id?
sys_id is a 32-character unique ID that ServiceNow automatically generates for every record in every table.
It is mainly used internally (backend) to uniquely identify a record.
sys_id = Always generated automatically for every record. You cannot stop it.

sys_id is the unique id generated by the system for each record

Yes. **`sys_id` is always generated**, whether Auto Number is enabled or not.

Here's the difference:

| Auto Number | `sys_id` Generated? | Auto Number Field Generated? |
| ----------- | ------------------- | ---------------------------- |
| ❌ Disabled  | ✅ Yes               | ❌ No                         |
| ✅ Enabled   | ✅ Yes               | ✅ Yes                        |

### Example

Suppose you create a Loan record.

**Without Auto Number**

| sys_id                             | Loan Number |
| ---------------------------------- | ----------- |
| `6f4c8d4edb123410f3d5a6b5ca9619d2` | *(empty)*   |

**With Auto Number Enabled**

| sys_id                             | Loan Number   |
| ---------------------------------- | ------------- |
| `6f4c8d4edb123410f3d5a6b5ca9619d2` | `LOAN0001000` |

So every record has **two identifiers** (if Auto Number is enabled):

* **`sys_id`** → Internal, hidden, used by ServiceNow (always exists).
* **Auto Number** (e.g., `LOAN0001000`) → Human-readable, shown to users (optional).

**Easy way to remember:**

* `sys_id` = **System ID** (mandatory, always generated)
* Auto Number = **Business ID** (optional, generated only if you enable it)


Can you see the sys_id?

Yes.

You can:

Open any record.
Right-click the form header.
Choose Configure → Form Layout (or Form Design).
Add the sys_id field to the form.

sys_db_object → Stores the definition of your table (e.g., x_company_loan exists).
sys_dictionary → Stores the definition of fields (e.g., sys_id, number, customer, amount).

**Very short:**

Every ServiceNow object (table, field, form, etc.) has a **backend (technical) name** because ServiceNow uses it internally for:

* ✅ Scripts (GlideRecord)
* ✅ APIs
* ✅ Business Rules
* ✅ Client Scripts
* ✅ Reference fields
* ✅ ACLs and Flows

**Example:**

* Display Name: **User**
* Backend Name: **`sys_user`**

Users see **User**, but developers and ServiceNow use **`sys_user`**.

The Extensible checkbox in ServiceNow means:

It allows other tables to inherit (extend) this table in the future.

Simple example

Suppose you create a table:

Bank

Bank Name
IFSC Code
Address

If you check Extensible ✅, later you can create another table:

Private Bank (extends Bank)

Bank Name ✅ (inherited)
IFSC Code ✅ (inherited)
Address ✅ (inherited)
Interest Rate (new field)

Or another table:

Government Bank (extends Bank)

Bank Name ✅
IFSC Code ✅
Address ✅
Government Scheme (new field)

Note: while creating private and govt. bank you have to give reference of this
bank table in their extends table field

So Private Bank and Government Bank automatically get all the fields from Bank.

If Extensible is NOT checked ❌

No other table can extend your Bank table. It becomes a standalone table.
